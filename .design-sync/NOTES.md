# Синхронизация с claude.ai/design — заметки

Проект: `WOW — публичная витрина`, `44c83474-a9bd-4d9d-8559-2222b9e5d5b4`
(https://claude.ai/design/p/44c83474-a9bd-4d9d-8559-2222b9e5d5b4).
Первая синхронизация — 2026-07-31.

## Главное: штатный конвертер тут не работает

Скилл `/design-sync` рассчитан на React-библиотеку: он собирает `_ds_bundle.js`
из `dist/` npm-пакета, чтобы агент дизайна импортировал компоненты из
`window.<namespace>`. У витрины ни пакета, ни сборки, ни React — дизайн-система
это токены, общий CSS и статические HTML-превью.

Поэтому раскладка собирается своим сборщиком **`.design-sync/build.mjs`**, но по
тому же контракту, который проверяет `package-validate.mjs`. Запускать
`package-build.mjs` на этом репозитории бесполезно — не пытаться.

`window.WOWShowcase` уезжает пустым намеренно: импортировать нечего. Агент
собирает страницы разметкой с классами из `_ds_bundle.css`. Это записано первым
абзацем в `conventions.md` — если оттуда пропадёт, агент начнёт выдумывать
импорты.

## Как пересинхронизировать

```bash
node .design-sync/build.mjs                      # → ds-bundle/
DS_CHROMIUM_PATH="$LOCALAPPDATA/ms-playwright/chromium-1223/chrome-win64/chrome.exe" \
  node .ds-sync/package-validate.mjs ./ds-bundle # должен выйти с 0
```

`.ds-sync/` — это скопированные из скилла `package-validate.mjs`, `lib/`
и `storybook/` плюс `npm i playwright`. Каталог в `.gitignore`, на свежем клоне
его надо пересоздать (строка `cp -r` есть в SKILL.md скилла, §2 шаг 7).

**Про playwright:** в системе уже лежит кэш `chromium-1223`, но новой раскладкой
(`chrome-win64/chrome.exe`, а не `chrome-linux/`). Подбирать версию playwright
под ревизию не нужно — проще передать путь к бинарнику через `DS_CHROMIUM_PATH`,
`package-validate.mjs` это поддерживает. Ставить 200 МБ браузера не надо.

`curl` к `raw.githubusercontent.com` из этой среды падает на проверке отзыва
сертификата (`CRYPT_E_REVOCATION_OFFLINE`). К `fonts.googleapis.com`
и `fonts.gstatic.com` — работает.

## Что было починено по дороге

- **Превью не подключали стили вообще.** После коммита a0a89c8 («превью
  переписаны полноценными HTML-документами») ни в одном файле не осталось
  `<link>` на `tokens.css`: все `var(--*)` были не определены, всё
  отрисовывалось системным шрифтом без единого токена. Теперь превью
  подключают `../index.css` и `../preview.css`.
- **Классы жили внутри `<style>` каждого превью** — переиспользовать их было
  нельзя. Вынесены в `design-system/components.css`.
- **Коллизии имён при выносе** (одно имя значило разное в разных превью):
  `.ava` 46px в строке выдачи против 72px в шапке канала, `.plat` 18 против 22,
  `.ver` 14 против 18, `.row` в выдаче против строки шкалы в типографике.
  Решение: база плюс модификатор `--lg`, а `.row` в типографике переименован
  в карточный `.spec-row`. Если будешь добавлять компонент — проверяй, не занято
  ли имя.
- **Шрифта не было.** Onest положен в `design-system/fonts/`: вариативный,
  один woff2 на подмножество символов, четыре файла (~64 КБ), лицензия OFL.
  Google отдаёт один и тот же файл на все запрошенные веса — плодить по файлу
  на вес не нужно.

## Что где лежит

| Файл | Что это |
|---|---|
| `design-system/index.css` | точка входа: шрифт → токены → компоненты |
| `design-system/tokens.css` | палитра, шкала, плотность, форма |
| `design-system/components.css` | словарь классов витрины |
| `design-system/preview.css` | каркас карточек, в витрину не уезжает |
| `design-system/components/*.html` | превью, первой строкой маркер `@dsCard` |
| `.design-sync/conventions.md` | шапка README, её читает агент дизайна |
| `.design-sync/prompts/*.prompt.md` | документация компонентов, тоже для агента |
| `.design-sync/build.mjs` | сборщик выгрузки |

Имя каталога компонента в выгрузке — латиницей (`components/ui/Row/`), потому
что оно попадает в URL. Человеческое имя группы живёт в маркере `@dsCard`
(`Основа`, `Компоненты`) — его и показывает панель.

## На что смотреть при следующей синхронизации

- **`conventions.md` рассыхается первой.** Там перечислены классы и токены
  поимённо. Добавили класс или переименовали токен — проверить шапку скриптом,
  который сверяет имена с собранным CSS, и починить. Агент верит написанному:
  несуществующий класс он вставит в разметку и молча получит неоформленную
  страницу. Проверка одноразовая, лежит в scratchpad-е прогона — проще написать
  заново, чем искать.
- **`prototype/` живёт своей жизнью.** `prototype/style.css` на дизайн-систему
  ещё не переведён: там осталась старая вёрстка с синим акцентом и тенями.
  Пока это два независимых источника вида — расходятся молча. Перевод прототипа
  на `design-system/index.css` задачей не ставился.
- **Наполнение скорингового бейджа не решено** — в `ScoreBadge.prompt.md` это
  записано прямым запретом придумывать расшифровку. Когда решится, поправить
  и превью, и промпт.
- **Логотип и название — заглушка** («Блогеры России»), домен не куплен.
- **Якорь `_ds_sync.json` — свой.** Хеши считает `build.mjs` по содержимому
  карточек, штатный `renderHashFor` тут неприменим (он завязан на манифест
  историй storybook). `package-validate.mjs` пересчёт пропускает, потому что
  `.stories-map.json` мы не пишем. Если однажды раскладку начнёт собирать
  штатный конвертер — якорь надо будет выкинуть, а не мигрировать.
