# WOW Public Showcase — инструкции агенту

## CHANGELOG — ОБЯЗАТЕЛЬНО

После каждого выполненного запроса пользователя добавь запись в `CHANGELOG.log` в корне проекта.
Формат:

```
ГГГГ-ММ-ДД — <короткий заголовок>
Задача: <что попросил пользователь, 1-2 предложения>
Результат:
  ◦ <пункт 1>
  ◦ <пункт 2>
Файлы: <количество изменённых файлов>
```

Не пропускай ни одного запроса. Пиши по-русски, кратко, по сути. Тот же формат, что в
датаколлекторе и внутренней витрине.

## Что это за репозиторий

Вёрстка публичной витрины — статика, без бэкенда. Данные лежат готовым срезом в
`prototype/data.js` (в git не хранится, см. README).

**Границы, их важно держать:**
- здесь только то, что видно на экране: разметка, стили, клиентская логика;
- расчёт метрик, запросы к базе, что именно считаем и откуда — не здесь, это датаколлектор и
  внутренняя витрина;
- URL-схема, кросс-ссылки, посадочные страницы, sitemap и прочее SEO — не здесь, это T-21;
- задачи, решения и переписка с заказчиком — в PM-репозитории `WOWlist_manage`.

## Работа с данными

`prototype/data.js` содержит реальный срез с прода, в том числе **наименования
рекламодателей-физлиц (ФИО)**. Репозиторий публичный. Файл в `.gitignore` — не коммитить,
не переносить его содержимое в примеры, не вставлять фрагменты в README и в задачи.

Если нужен пример структуры — `prototype/data.example.js`, он синтетический.

## Стиль

Текст интерфейса — живым языком, без длинных тире. **WOW всегда капсом** (требование заказчика,
относится ко всем пользовательским надписям; URL и технические строки не трогаем).

Ответы агента — кратко и по делу, без вступлений и перечисления невыбранных вариантов.

## Проверка изменений

Статика, сборки нет:

```bash
cd prototype && python -m http.server 8080   # http://localhost:8080/index.html
```

Смотреть глазами обе страницы — выдачу и карточку канала, включая мобильную ширину.
